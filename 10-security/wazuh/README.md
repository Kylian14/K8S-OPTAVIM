# Phase 7 — Wazuh SIEM

Wazuh 4.8 stack in a simplified single-node deployment:

| Component | Role | Resources |
|---|---|---|
| **wazuh-indexer** | OpenSearch data store | 1 replica, 10 Gi PV |
| **wazuh-manager** | Management server + agent endpoint | 1 replica, 5 Gi PV |
| **wazuh-dashboard** | Web UI (OpenSearch Dashboards) | 1 replica |

## Apply order

```bash
# 1. Secrets + cert config
kubectl apply -f 10-security/wazuh/01-secret.yaml
kubectl apply -f 10-security/wazuh/02-certs-config.yaml

# 2. Cert generation (one-shot Job, ~30 s)
kubectl apply -f 10-security/wazuh/03-certs-job.yaml
kubectl wait -n security --for=condition=Complete job/wazuh-certs-generator --timeout=120s
kubectl get secrets -n security | grep wazuh-certs
# Expected: wazuh-certs-admin, -indexer, -manager, -dashboard

# 3. Indexer (OpenSearch) — starts first
kubectl apply -f 10-security/wazuh/04-indexer.yaml
# Wait for the pod to be Running (it stays Ready=false as long as the security
# index is not initialized)
until kubectl get pod -n security wazuh-indexer-0 -o jsonpath='{.status.phase}' | grep -q Running; do sleep 5; done

# 4. Initialize the security index (internal_users, roles, etc.)
kubectl exec -n security wazuh-indexer-0 -- bash -c '
  export JAVA_HOME=/usr/share/wazuh-indexer/jdk
  bash /usr/share/wazuh-indexer/plugins/opensearch-security/tools/securityadmin.sh \
    -cd /usr/share/wazuh-indexer/opensearch-security/ \
    -icl -key /usr/share/wazuh-indexer/certs/admin-key.pem \
    -cert /usr/share/wazuh-indexer/certs/admin.pem \
    -cacert /usr/share/wazuh-indexer/certs/root-ca.pem \
    -h localhost -nhnv'
# The pod becomes Ready after this (the readinessProbe can read /_cluster/health)

# 5. Manager (depends on the indexer to push its alerts)
kubectl apply -f 10-security/wazuh/05-manager.yaml
kubectl rollout status sts/wazuh-manager -n security --timeout=300s

# 6. Dashboard (UI + OIDC SSO via Keycloak)
kubectl apply -f 10-security/wazuh/06-dashboard.yaml
kubectl apply -f 10-security/wazuh/07-ingressroute.yaml

# 7. Create the Wazuh OIDC client in Keycloak + inject the secret
bash 07-keycloak/03-post-deploy-realm.sh
```

## Access

- **Dashboard**: `https://wazuh.optavim.corp`
- Local login (fallback): `admin` / `admin`
  - ⚠️ Lab default. The `admin` user is marked `reserved` in `internal_users.yml` → not modifiable via the API. To change the password in production:
    1. Generate a hash: `kubectl exec -n security wazuh-indexer-0 -- bash /usr/share/wazuh-indexer/plugins/opensearch-security/tools/hash.sh -p "NEW_PASSWORD"`
    2. Create a ConfigMap that overrides `internal_users.yml` with the new hash
    3. Re-mount + re-run `securityadmin.sh`

## DNS to configure

`wazuh.optavim.corp → 10.1.50.100` (HAProxy VIP)

## Keycloak SSO integration (OpenID Connect)

Not wired by default — Wazuh uses local `admin/admin`. To enable OIDC via the OPTAVIM realm:

### 1. Add `openid_auth_domain` in `config.yml`

```bash
kubectl exec -n security wazuh-indexer-0 -- bash -c '
cat >> /usr/share/wazuh-indexer/opensearch-security/config.yml <<EOF

        openid_auth_domain:
          http_enabled: true
          transport_enabled: false
          order: 1
          http_authenticator:
            type: openid
            challenge: false
            config:
              subject_key: preferred_username
              roles_key: groups
              openid_connect_url: https://auth.optavim.corp/realms/OPTAVIM/.well-known/openid-configuration
          authentication_backend:
            type: noop
EOF'
```

### 2. Re-apply the config

```bash
kubectl exec -n security wazuh-indexer-0 -- bash -c '
export JAVA_HOME=/usr/share/wazuh-indexer/jdk
/usr/share/wazuh-indexer/plugins/opensearch-security/tools/securityadmin.sh \
  -cd /usr/share/wazuh-indexer/opensearch-security/ \
  -icl -key /usr/share/wazuh-indexer/certs/admin-key.pem \
  -cert /usr/share/wazuh-indexer/certs/admin.pem \
  -cacert /usr/share/wazuh-indexer/certs/root-ca.pem \
  -h localhost -nhnv'
```

### 3. Enable OIDC on the dashboard side

Patch `opensearch_dashboards.yml` (via ConfigMap mount) with:

```yaml
opensearch_security.auth.type: "openid"
opensearch_security.openid.connect_url: "https://auth.optavim.corp/realms/OPTAVIM/.well-known/openid-configuration"
opensearch_security.openid.client_id: "wazuh"
opensearch_security.openid.client_secret: "<OIDC_CLIENT_SECRET from the wazuh-secret Secret>"
opensearch_security.openid.base_redirect_url: "https://wazuh.optavim.corp"
```

### 4. Role mapping

In Keycloak, create a "groups" mapper → claim `groups` in the OIDC token. Then in `roles_mapping.yml`:

```yaml
all_access:
  reserved: false
  backend_roles:
    - "wazuh-admins"
```

Then re-run securityadmin.sh.

## Points of attention

- **Certs**: generated by the `wazuh-certs-generator` Job. If you need to regenerate (FQDN change, expiration), delete the Job + the 4 `wazuh-certs-*` Secrets and reapply the Job.
- **Resources**: the OpenSearch indexer is hungry (1 GB RAM minimum). Watch it via Grafana.
- **OIDC**: the OIDC setup on the OpenSearch Security side is complex, it may require a manual edit of `config.yml` in the `opensearch-security` Secret (see the Wazuh docs).
- **Single-node deployment**: production needs 3 HA indexer nodes; our lab setup runs on a single one.
