## Dashboards-as-code mechanism

1. Edit a dashboard JSON under `09-monitoring/grafana/dashboards/*.json`
2. `cd 09-monitoring/grafana && ./dashboards/sync.sh` (regenerates `05-dashboards-cm.yaml`)
3. `kubectl apply -f 09-monitoring/grafana/05-dashboards-cm.yaml`
4. Grafana detects the changes via the file provider (`updateIntervalSeconds: 30`), no restart needed.

Same for branding: edit under `branding/`, run `branding/sync.sh`, apply, then `kubectl rollout restart deploy/grafana` (the initContainer replays the overlay).

## Exporters mechanism

Three patterns:
- **Native**: env vars in the existing app (Keycloak `KC_METRICS_ENABLED`, Traefik `--metrics.prometheus`, MinIO `MINIO_PROMETHEUS_AUTH_TYPE=public`)
- **Operator-managed**: MariaDB CR `spec.metrics.enabled: true`, the operator creates the `mariadb-galera-metrics` Deployment + Service:9104 (requires the ServiceMonitor CRD)
- **Standalone Deployment**: redis-exporter, blackbox-exporter, snmp-exporter, haproxy-exporter

Prometheus discovery:
- **Annotation-based** (default): pods/services with the annotation `prometheus.io/scrape="true"`
- **Static targets** (MariaDB metrics, blackbox probes, snmp pfSense)

## TODOs / open items

| Item | Why | How to resolve |
|---|---|---|
| **PHP-FPM sidecars** (Nextcloud, Dolibarr, OrangeHRM) | Risk of stripping app env vars (cf. Keycloak incident 2026-06-08) | Separate session: ConfigMap `pm.status_path` + one sidecar per app + post-apply checklist |
| **HAProxy stats endpoint** | External VM `10.1.50.100` does not expose `:8404/stats;csv` | SSH into HAProxy and enable `frontend stats / bind 0.0.0.0:8404 / stats enable / stats uri /stats` in `haproxy.cfg` |
| **SNMP pfSense** | SNMP service not enabled on the HQ and branch pfSense | Services -> SNMP -> Enable, v2c community `CHANGE_ME_snmp_community`, FW rule 161/udp from monitoring |
| **nextcloud-exporter** | Not created yet (needs an app password) | Create a `prometheus_ro` Nextcloud account + app password -> K8s Secret + Deployment experimental/nextcloud-exporter |
| **ServiceMonitor CRD** | Installed but with no operator to act on it | Acceptable: we scrape via annotation-based; otherwise install the full prometheus-operator |
| **Full Prometheus Operator** | Not in place, annotation-based is enough for 95% of cases | Optional: only if we want declarative PrometheusRule/Alertmanager |

## End-to-end verification

```bash
# 1. Pods OK
kubectl get pods -n monitoring -o wide | grep -v Completed
kubectl get pods -n databases -l app=redis-exporter
kubectl get pods -n databases -l app.kubernetes.io/instance=mariadb-galera-metrics

# 2. Prometheus targets
kubectl exec -n monitoring deploy/prometheus -- wget -qO- http://localhost:9090/api/v1/targets | \
  python3 -c "import json,sys;d=json.load(sys.stdin);print('\n'.join(sorted(set(t['labels']['job']+': '+t['health'] for t in d['data']['activeTargets']))))"

# 3. Dashboards loaded
kubectl exec -n monitoring deploy/grafana -- curl -s -u admin:$PWD \
  "http://localhost:3000/api/search?tag=optavim" | jq 'length'
# expected: 10

# 4. Metrics endpoint for each exporter (from a debug curl pod)
kubectl run dc --rm -i --image=curlimages/curl:latest --restart=Never --command -- sh -c "
  curl -s http://traefik-metrics.ingress.svc:8082/metrics | grep '^traefik_' | head -3
  curl -s http://redis-exporter.databases.svc:9121/metrics | grep '^redis_' | head -3
  curl -s http://mariadb-galera-metrics.databases.svc:9104/metrics | grep '^mysql_' | head -3
  curl -s http://minio.mariadb-backup.svc:9000/minio/v2/metrics/cluster | grep '^minio_' | head -3
"

# 5. UI smoke test
# Open https://grafana.optavim.corp -> OIDC login -> Browse -> Tag: optavim -> 10 dashboards
# On "Executive Overview": all panels show data
```
