# Keycloak: OPTAVIM custom theme

`optavim` theme for the Keycloak **login** and **account console** pages.

- **Colors**: corporate navy blue -> bright blue (gradient)
- **Logo**: "OPTAVIM" text in CSS (no image file)
- **Slogan**: "Optimisation · Vision · Ambition"
- **Compatible**: Keycloak 24+ (inherits `keycloak.v2` login + `keycloak.v3` account)

## Structure

```
themes/
├── optavim/
│   ├── login/
│   │   ├── theme.properties          # parent=keycloak.v2 + import css/login.css
│   │   └── resources/css/login.css   # OPTAVIM custom CSS (~7 KB)
│   └── account/
│       ├── theme.properties          # parent=keycloak.v3
│       └── resources/css/account.css # account console overrides (~1.5 KB)
├── 01-theme-configmap.yaml           # ConfigMap auth/keycloak-theme-optavim
├── 02-statefulset-patch.yaml         # StatefulSet patch (volume + subPath mounts)
├── 03-apply-realm-theme.sh           # Apply loginTheme=optavim to the realms
└── README.md
```

## Deployment

```bash
cd 07-keycloak/themes/

# 1. ConfigMap with the 4 theme files
kubectl apply -f 01-theme-configmap.yaml

# 2. Patch the keycloak StatefulSet (adds volume + 4 subPath volumeMounts)
kubectl patch sts -n auth keycloak --patch-file 02-statefulset-patch.yaml

# 3. Wait for rollout (2 Keycloak replicas)
kubectl rollout status sts -n auth keycloak --timeout=300s

# 4. Apply the theme to the OPTAVIM + master realms
bash 03-apply-realm-theme.sh
```

## Testing locally without deploying (CSS preview only)

No local preview is possible: the theme depends on the parent `.ftl` (keycloak.v2). To iterate quickly on the CSS, deploy then edit the ConfigMap and reload the pod.

## Updating the theme (after a CSS change)

```bash
# 1. Edit optavim/login/resources/css/login.css

# 2. Rebuild the ConfigMap (script regenerates inline contents)
cd 07-keycloak/themes/
# 01-theme-configmap.yaml is auto-generated by a local build
# (see the git pre-commit hook, or regenerate manually):
cat 01-theme-configmap.yaml | head  # check that the CSS is up to date

# 3. Apply + restart Keycloak to purge the theme cache (if cache enabled)
kubectl apply -f 01-theme-configmap.yaml
kubectl rollout restart sts -n auth keycloak
```

> **Note**: in `02-statefulset-patch.yaml`, `KC_SPI_THEME_CACHE_THEMES=false` is set so the CSS can be updated without redeploying the pod. In stable production, remove the two `KC_SPI_THEME_CACHE_*` vars to re-enable the cache (better performance at ~5000 logins/day).

## Rollback

```bash
# 1. Set loginTheme back to default
bash 03-apply-realm-theme.sh OPTAVIM master  # but override with loginTheme="" via kcadm

# Simpler:
kubectl exec -n auth keycloak-0 -c keycloak -- bash -c '
  /opt/keycloak/bin/kcadm.sh config credentials --server http://localhost:8080 \
    --realm master --user $KEYCLOAK_ADMIN --password $KEYCLOAK_ADMIN_PASSWORD &&
  /opt/keycloak/bin/kcadm.sh update realms/OPTAVIM -s "loginTheme=" -s "accountTheme="
'

# 2. Remove the mount + ConfigMap (optional)
kubectl rollout restart sts -n auth keycloak
kubectl delete configmap -n auth keycloak-theme-optavim
```
